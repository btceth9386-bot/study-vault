# Highlights

- `Product page: Why AWS DevOps Agent?` AWS positions DevOps Agent as an always-available teammate spanning code change review, release testing, incident investigation, mitigation planning, and operational improvement.
- `Product page: Production Operations Benefits` The service correlates operational data with code repositories, CI/CD pipelines, runbooks, and observability tools, then routes findings through channels such as Slack, ServiceNow, and PagerDuty.
- `Product page: Release Management Benefits` Release readiness checks include standards adherence, dependency impacts, access controls, cross-repository dependencies, deterministic verification, and blast-radius reasoning.
- `User Guide: About AWS DevOps Agent` The agent works by learning resources and relationships, working with observability tools and pipelines, correlating telemetry with code and deployment data, and supporting multicloud and hybrid environments.
- `User Guide: What are DevOps Agent Spaces?` Agent Spaces act as logical containers for AWS account configurations, third-party integrations, and access permissions.
- `User Guide: What is a DevOps Agent Topology?` Topology graphs help the agent identify affected components, understand blast radius, trace impact paths, and produce preventative recommendations.
- `User Guide: Learned Skills` AWS documents learned skills such as Agent Space Understanding, Understanding Code Dependencies, Understanding Pipeline Topology, and Tool Use Best Practices.
- `User Guide: DevOps Agent Memories` Memories are markdown knowledge items grouped into memory stores and selected through progressive disclosure during investigations.
- `User Guide: Release readiness code reviews` Release readiness reviews can run in developer workflows and include built-in guardrails, sequential review phases, repository enablement, and optional private VPC access for verification.
- `User Guide: Release testing` Release testing generates change-specific plans for web and API applications, using test profiles and results from release readiness review rather than only static regression suites.
- `User Guide: Autonomous incident response` Investigations can start from alerts or tickets, triage events, classify whether investigation is needed, and accept feedback to correct triage decisions.
- `User Guide: Proactive incident prevention` The service evaluates historical incidents and recommendations to strengthen observability, infrastructure, deployment pipelines, and application resilience.
- `User Guide: Connect to DevOps Agent remote servers` DevOps Agent exposes remote server endpoints for MCP and A2A clients, with access tokens and SigV4 authentication options.
- `User Guide: Connecting MCP Servers` External MCP servers can be registered with security review, authorization flow, and account-level configuration before being associated with Agent Spaces.
- `User Guide: Invoking DevOps Agent through Webhook` Webhooks can trigger investigations using HMAC or bearer-token authentication, making external alert systems first-class initiators.
- `User Guide: EventBridge integration` DevOps Agent emits investigation and mitigation events that can be matched by EventBridge rules for event-driven automation.
- `User Guide: Security` Security coverage includes Agent Spaces, regional data flow, Bedrock inference routing, IAM permissions, identity providers, encryption at rest, PrivateLink, and compliance validation.
- `User Guide: What's new` Recent 2026 updates include scoped access tokens for MCP/A2A, memories, remote server endpoints, custom agents, pipeline topology, asset APIs, webhooks, and expanded integrations.
