# Highlights

- `p. 6` Vibe coding and agentic engineering occupy a spectrum from informal intent prompting to constrained, disciplined implementation.
- `p. 7` Security asks whether an agent remained within its boundary; evaluation asks whether the bounded result is worth shipping.
- `p. 8` A model becomes an agent through a harness that provides state, tools, feedback loops, and enforceable constraints.
- `pp. 9-12` The seven-pillar baseline spans infrastructure, data, model, application/runtime, identity, observability/security operations, and governance.
- `pp. 13-14` Generated code should run in ephemeral network-isolated sandboxes, while dependency provenance and governed egress reduce supply-chain risk.
- `pp. 17-19` Dedicated agent identities, contextual authorization, zero ambient authority, and just-in-time token downscoping constrain autonomous tool use.
- `pp. 19-20` A “Vibe Diff” translates a proposed high-risk action into plain language before strong human authorization.
- `pp. 20-23` Agentic Red, Blue, and Green teams continuously probe, detect, quarantine, and repair security failures.
- `pp. 24-25` A Vibe Trajectory and Runtime Agent Bill of Materials expose intent drift, trust decay, cost loops, and changing blast radius.
- `pp. 28-30` Coding-agent evaluation is difficult because intent is underspecified, users may not be able to review code, and each turn mutates codebase state.
- `pp. 29-33` Seven evaluation dimensions require a portfolio of automated tests, security scans, model judges, browser tests, trace inspection, human review, and online evaluation.
- `pp. 35-39` Practical evaluation should infer a rubric from the session prefix, judge rendered artifacts, measure session convergence, and mine user corrections as labeled failures.
